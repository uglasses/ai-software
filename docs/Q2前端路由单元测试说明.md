# 前端路由配置单元测试说明

本文档说明本项目中 **Vue Router 路由配置** 的单元测试：测什么、怎么跑、执行流程及维护约定。

## 1. 概述

| 项目 | 说明 |
| --- | --- |
| 测试类型 | 单元测试（路由配置校验，不渲染页面、不请求后端） |
| 测试框架 | [Vitest](https://vitest.dev/) 2.x |
| 运行环境 | Node.js + jsdom（见 `frontend/vite.config.js` 中 `test.environment`） |
| 被测模块 | `frontend/src/router/index.js` |
| 测试文件 | `frontend/src/router/index.test.js` |
| 用例数量 | 1 个测试套件、1 条用例（另见 `src/api/*.test.js`、`src/stores/user.test.js`，运行 `npm test` 一并执行） |

**测试目的：** 在重构或新增页面时，自动确认核心业务页面的 **路由 `name` 仍已在路由表中注册**，避免菜单/编程式导航因路由名缺失而失效。

## 2. 如何执行

在 `frontend` 目录下执行：

```bash
npm test
```

等价于 `vitest run`（跑完即退出，非监听模式）。

**前置条件：**

- 已执行 `npm install` 安装依赖（含 `vitest`、`jsdom`）。
- **不需要** 启动 `npm run dev`。
- **不需要** 后端 `8080` 或 AI 服务。

**仅跑路由测试（可选）：**

```bash
npx vitest run src/router/index.test.js
```

**期望输出示例：**

```text
✓ src/router/index.test.js
  ✓ router
    ✓ registers the core project pages

Test Files  1 passed (1)
Tests       1 passed (1)
```

## 3. 执行流程

```text
npm test
  → package.json scripts.test 调用 vitest run
  → Vitest 扫描 **/*.{test,spec}.js 等文件
  → 加载 vite.config.js（含 test.environment: jsdom）
  → 执行 index.test.js
       → import router from './index'（执行 index.js 中的 createRouter）
       → router.getRoutes() 获取已注册路由列表
       → 对每条断言 expect(routeNames).toContain('...')
  → 输出通过/失败并退出
```

说明：

- `import './index'` 会创建路由器实例并注册 `routes`，但页面组件为懒加载 `() => import(...)`，**不会**加载或渲染 `.vue` 文件。
- `beforeEach` 钩子会随模块加载而注册，本用例不模拟导航，一般不触发标题修改逻辑。

## 4. 被测路由配置摘要

路由定义见 `frontend/src/router/index.js`：

- **登录页：** `path: /login`，`name: login`（独立路由，无 MainLayout）。
- **主布局：** `path: /`，使用 `MainLayout`，默认 `redirect: /dashboard`。
- **子路由：** 挂在 `/` 下的 `children`，对应各业务页面。

完整路径与 `name` 对照表：

| 路由 name | 路径（相对或绝对） | 页面说明 | 是否纳入本测试断言 |
| --- | --- | --- | --- |
| `login` | `/login` | 登录 | 否 |
| `dashboard` | `/dashboard` | 首页看板 | 是 |
| `jobs` | `/jobs` | 岗位列表 | 是 |
| `job-detail` | `/jobs/:id` | 岗位详情 | 否 |
| `analysis` | `/analysis` | 数据分析 | 是 |
| `resume` | `/resume` | 简历辅助 | 是 |
| `resume-history` | `/resume/history` | 简历历史 | 是 |
| `resume-history-detail` | `/resume/history/:id` | 简历详情 | 是 |
| `admin` | `/admin` | 后台管理 | 是 |

未写入断言的路由（`login`、`job-detail`）仍存在于配置中；若需防止误删，可后续在用例中补充 `toContain('login')` 等。

## 5. 用例说明

**套件：** `describe('router', ...)`

**用例：** `it('registers the core project pages', ...)`

**步骤：**

1. 调用 `router.getRoutes()` 获取 Vue Router 解析后的路由记录列表。
2. 映射为 `route.name` 数组（含嵌套子路由的 name）。
3. 断言数组中包含以下 7 个名称：
   - `dashboard`
   - `jobs`
   - `analysis`
   - `resume`
   - `resume-history`
   - `resume-history-detail`
   - `admin`

**通过条件：** 上述 `name` 均存在于路由表中。

**失败典型场景：**

- 删除或重命名了某条子路由的 `name`，但未同步改测试。
- 将页面从 `children` 移出导致 `getRoutes()` 中不再出现对应 `name`。

## 6. 测试范围边界

### 6.1 本测试覆盖

- 路由模块能正常 `import` 并完成 `createRouter`。
- 核心业务页的路由 **命名** 已注册。

### 6.2 本测试不覆盖

| 内容 | 说明 |
| --- | --- |
| 页面 UI / 组件逻辑 | 不挂载 Vue 应用，不使用 `@vue/test-utils` 渲染 |
| 路由守卫与登录鉴权 | 未模拟 `beforeEach` 跳转或 token 判断 |
| 实际 URL 导航 | 未调用 `router.push` / `router.resolve` |
| `meta.title`、文档标题 | 未断言 `beforeEach` 行为 |
| 懒加载组件是否存在的文件路径 | 仅校验路由表，不校验 `.vue` 文件是否在磁盘上 |
| 后端 API | 与 HTTP 无关 |

以上如需保障，应另写组件测试、E2E 或接口测试。

## 7. 相关配置

**`frontend/package.json`**

```json
"scripts": {
  "test": "vitest run"
}
```

**`frontend/vite.config.js`**

```javascript
test: {
  environment: 'jsdom',
  globals: true
}
```

路径别名 `@` → `src` 与开发构建一致，保证 `index.js` 中 `@/layouts/...` 在测试中可被 Vite 解析（本用例不实际加载这些模块）。

## 8. 维护约定

1. **新增核心业务页（需出现在主导航或 `router.push({ name })`）时：**
   - 在 `index.js` 的 `children`（或顶层）增加路由并设置唯一 `name`。
   - 在 `index.test.js` 中增加对应的 `expect(routeNames).toContain('新 name')`。

2. **重命名路由 `name` 时：** 同步修改所有 `router-link` / `router.push` 引用处及本测试文件。

3. **仅改 `path` 不改 `name` 时：** 通常无需改测试。

4. **PR / 提交前：** 在 `frontend` 目录执行 `npm test`，确保路由测试与其它 `*.test.js` 一并通过。

## 9. 与项目其它测试的关系

| 模块 | 命令 | 关系 |
| --- | --- | --- |
| 前端 | `npm test` | 本文档描述的路由测试属于其中一部分 |
| 后端 | `mvn test` | 独立，测 Spring Boot API 与业务逻辑 |
| AI 服务 | `pytest` | 独立，测 FastAPI 与匹配算法 |

三端测试相互独立，可分别执行。
